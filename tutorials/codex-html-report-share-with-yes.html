Let Codex share a Playwright HTML report only after you say yes

When Codex finishes a Playwright (or Vitest / Jest HTML) run, the useful artifact is often a single report.html or playwright-report/index.html on disk. Screenshots lose the expandable failures and trace links. Emailing a zip is slow. This walkthrough adds one shell script plus a short rule in ~/.codex/AGENTS.md so you can say "share the Playwright report" and get a public link — but only after Codex has printed a preview and you have answered yes in chat.

It is the same two-call pattern as a generic HTML share helper, aimed at test reports rather than dashboards: preview first, publish only with --confirmed, and keep the owner token off the model transcript.

Why reports need a yes-gate

HTML reports can embed failure snippets, request URLs, and sometimes screenshot paths. Treat them as potentially sensitive. Codex must never publish unattended. The script therefore refuses to upload unless you pass --confirmed, and the AGENTS.md text forbids adding that flag until you reply yes in the conversation.

The script (~/.codex/bin/share-html.sh)

Save this, then chmod +x ~/.codex/bin/share-html.sh. It publishes a single HTML file to deed.page with one curl -T. No account is required for the first upload. The owner token is written to ~/.config/deed-page/token (mode 600) and masked in stdout so it never appears in the Codex transcript.

#!/usr/bin/env bash
# share-html.sh FILE [--confirmed]
# Without --confirmed: print a preview summary and exit (nothing leaves the machine).
# With --confirmed: publish FILE to a public deed.page URL. Agents pass --confirmed
# only after the human said yes in chat. The owner token is saved, never printed.
set -euo pipefail
FILE=${1:?usage: share-html.sh FILE [--confirmed]}
[ -f "$FILE" ] || { echo "No such file: $FILE"; exit 1; }
TITLE=$(grep -o -i -m1 '<title>[^<]*' "$FILE" | sed 's/<title>//I' || true)
if [ "${2:-}" != "--confirmed" ]; then
  echo "Ready to publish: $FILE ($(wc -c < "$FILE") bytes, title: ${TITLE:-none})"
  echo "This makes it public on the internet. Ask the user, then rerun with --confirmed."
  exit 0
fi
CONF=~/.config/deed-page; KEY=$(printf '%s' "$(realpath "$FILE")" | sha1sum | cut -c1-10)
SLUG=$(cat "$CONF/slug-$KEY" 2>/dev/null || echo "share-$(openssl rand -hex 4)")
TOK=${DEEDPAGE_TOKEN:-$(cat "$CONF/token" 2>/dev/null || true)}
set --; [ -n "$TOK" ] && set -- -H "Authorization: Bearer $TOK"
RESP=$(curl -sS -T "$FILE" "https://deed.page/v1/sites?slug=$SLUG" "$@" -H "X-Client: share-html-script")
NEW=$(printf '%s' "$RESP" | sed -n 's/.*"token": *"\(deed_tok_[^"]*\)".*/\1/p')
(umask 077; mkdir -p "$CONF"; printf '%s' "$SLUG" > "$CONF/slug-$KEY"
 [ -n "$NEW" ] && printf '%s' "$NEW" > "$CONF/token") || true
printf '%s' "$RESP" | sed 's/"token": *"[^"]*"/"token":"<saved>"/' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d.get("url") or d)'

Point the first argument at the report file Codex just wrote — for example playwright-report/index.html, a self-contained Playwright HTML report, or a one-file API demo page you asked it to generate after a failing test.

The section for ~/.codex/AGENTS.md

## Sharing HTML test reports
- When I ask you to share a Playwright, Vitest, Jest, coverage, or other HTML
  report (or a one-file API demo page), run
  `~/.codex/bin/share-html.sh <file>` first and show me the summary.
- Then ask "Publish this report to a public URL?" and stop. Only after I reply
  yes in this conversation, run
  `~/.codex/bin/share-html.sh <file> --confirmed` and give me the URL.
- Never add --confirmed on your own. Never open, cat, or print anything under
  ~/.config/deed-page/, and never paste the owner token anywhere.
- Prefer a single HTML file. If the report is a folder with many assets, say so
  and wait for instructions instead of uploading blindly.
- Re-sharing the same file path updates the same public address.

What a session looks like

You: run the checkout Playwright suite and share the HTML report
Codex: 3 passed, 0 failed. Ready to publish: playwright-report/index.html (184291 bytes, title: Playwright Test Report). Publish this report to a public URL?
You: yes
Codex: https://share-xxxxxxxx.deed.page/

What happened when I ran it

I exercised the script the same way Codex would, with a 471-byte fixture titled "Playwright Report — checkout.spec.ts". The preview call printed the size and title and created no new slug files. The --confirmed call returned a live https://share-xxxxxxxx.deed.page/ URL that served the fixture (HTTP 200). The token never appeared in the output. A DELETE against that slug returned 200 and the URL returned 404 a moment later.

Taking a report down

curl -X DELETE "https://deed.page/v1/sites/<slug>" \
  -H "Authorization: Bearer $(cat ~/.config/deed-page/token)"

The slug is the subdomain before .deed.page. Run the delete yourself rather than asking Codex, because it reads the token file.
