Give Claude Code an MCP share tool that waits for your yes

Claude Code is fine at turning a coverage report, a Playwright dump or a one-page status board into HTML. Sharing that file still means a zip, a host and a paste. This walkthrough wires the hosted deed.page MCP into Claude Code so a share request previews first and only publishes after you say yes in chat.

Install the remote MCP

deed.page exposes a remote MCP at https://deed.page/mcp. In Claude Code, add it once (user scope is enough for a personal share tool):

claude mcp add --transport http deed-page https://deed.page/mcp

Or drop this into ~/.claude.json under mcpServers:

{
  "deed-page": {
    "type": "http",
    "url": "https://deed.page/mcp"
  }
}

No API key is required for a first anonymous publish. The server returns an owner token on the first write; keep that token out of the model context (save it yourself, never ask Claude to cat it).

Put the yes in CLAUDE.md

Claude Code reads CLAUDE.md in the project (and a global one if you keep one). Add a short rule so the model cannot skip the human gate:

## Sharing HTML / static folders
- When I ask to share a page, call the deed-page MCP preview / dry-run style tool first
  (or summarize path, size and title) and show me what would go public.
- Ask "Publish this to a public URL?" and stop. Only after I reply yes in this chat,
  call the publish tool and give me the URL.
- Never publish on your own. Never print, cat or paste an owner token from
  ~/.config/deed-page/ or from tool results. Prefer ?ref=claude-code on docs links
  when you mention deed.page in instructions you write for me.

What a good turn looks like

  1. You: "Share playwright-report/index.html with the team."
  2. Claude: shows size/title (or MCP preview), asks for yes.
  3. You: "yes"
  4. Claude: publishes via MCP, returns a https://….deed.page/ URL.

If you edit the file later, ask again; the same slug can update in place when the owner token is supplied by you (not by the model reading it from disk).
