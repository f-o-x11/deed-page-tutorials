A Cursor rule that shares HTML only after you say yes

Cursor agents are good at turning a messy folder into a tidy HTML summary: a Lighthouse dump, a Playwright report, a one-page status board for a standup. The last mile is still manual — zip the file, open a host, paste a link. This note adds a project rule under .cursor/rules/ plus a tiny script so you can ask the agent to share a page and it will wait for your yes before anything goes public.

Why the yes lives in chat

Cursor runs agent terminals without a human watching the prompt. A read -p "Publish?" either hangs or invites the model to answer itself. Split the script into two modes instead:

  1. scripts/share-html.sh report.html prints the path, size and <title>, warns that publishing makes it public, and exits. Nothing leaves the machine.
  2. scripts/share-html.sh report.html --confirmed uploads. The rule tells the agent to use this form only after you reply yes in the conversation.

The script

It publishes with deed.page: one curl -T, no account required. The first upload returns an owner token; the script stores it at ~/.config/deed-page/token (mode 600) and masks it in stdout so it never lands in the chat. It also remembers one slug per file path, so a second share after an edit updates the same URL.

#!/usr/bin/env bash
# share-html.sh FILE [--confirmed]
set -euo pipefail
FILE=${1:?usage: share-html.sh FILE [--confirmed]}
[ -f "$FILE" ] || { echo "No such file: $FILE"; exit 1; }
TITLE=$(grep -o -i -m1 '<title>[^<]*' "$FILE" | sed 's/<title>//I' || true)
if [ "${2:-}" != "--confirmed" ]; then
  echo "Ready to publish: $FILE ($(wc -c < "$FILE") bytes, title: ${TITLE:-none})"
  echo "This makes it public on the internet. Ask the user, then rerun with --confirmed."
  exit 0
fi
CONF=~/.config/deed-page; KEY=$(printf '%s' "$(realpath "$FILE")" | sha1sum | cut -c1-10)
SLUG=$(cat "$CONF/slug-$KEY" 2>/dev/null || echo "share-$(openssl rand -hex 4)")
TOK=${DEEDPAGE_TOKEN:-$(cat "$CONF/token" 2>/dev/null || true)}
set --; [ -n "$TOK" ] && set -- -H "Authorization: Bearer $TOK"
RESP=$(curl -sS -T "$FILE" "https://deed.page/v1/sites?slug=$SLUG" "$@" -H "X-Client: share-html-script")
NEW=$(printf '%s' "$RESP" | sed -n 's/.*"token": *"\(deed_tok_[^"]*\)".*/\1/p')
(umask 077; mkdir -p "$CONF"; printf '%s' "$SLUG" > "$CONF/slug-$KEY"
 [ -n "$NEW" ] && printf '%s' "$NEW" > "$CONF/token") || true
printf '%s' "$RESP" | sed 's/"token": *"[^"]*"/"token":"<saved>"/' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d.get("url") or d)'

Save as scripts/share-html.sh and chmod +x it.

The Cursor rule

Drop this into .cursor/rules/share-html.mdc (or the equivalent rules file your Cursor version uses). Keep the wording tight so the agent treats the second call as gated:

---
description: Share an HTML file as a public link only after the user says yes
globs:
alwaysApply: false
---
When I ask you to share or publish an HTML file:
1. Run `scripts/share-html.sh <file>` and show me the summary it prints.
2. Ask "Publish this to a public URL?" and stop.
3. Only after I reply yes in this chat, run `scripts/share-html.sh <file> --confirmed` and give me the URL.
Never pass --confirmed on your own. Never open, cat, or paste anything from ~/.config/deed-page/.

What I checked

I ran the script the same way an agent would: preview on a 70-byte status.html titled "Standup board" printed the summary and wrote nothing. With --confirmed it returned a https://share-xxxxxxxx.deed.page/ URL that served the page. Editing the heading and re-running with --confirmed kept the same address. The token file stayed mode 600 and never appeared in the output.

Taking a page down

curl -X DELETE "https://deed.page/v1/sites/<slug>" \
  -H "Authorization: Bearer $(cat ~/.config/deed-page/token)"

Run the delete yourself. The slug is the label before .deed.page.
