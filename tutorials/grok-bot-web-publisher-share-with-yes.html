Let Grok Bot draft a business page, then publish only after you say yes

Grok Bot is strong at turning a short brief into a clean one-page business site: services, hours, a contact block, maybe a simple price table. The awkward part is going from that HTML file to a public URL without the bot publishing on its own. This note adds a tiny share-html.sh helper plus a standing instruction so Grok previews first and only uploads after you type yes in the chat.

Why preview and yes are separate

Agent shells are not a terminal you are staring at. A read -p "Publish?" either hangs or invites the model to answer itself. Split the helper into two modes instead:

  1. share-html.sh site.html prints path, byte size and the <title>, warns that publishing makes the page public, and exits. Nothing leaves your machine.
  2. share-html.sh site.html --confirmed uploads. Your standing instruction tells Grok to use this form only after you reply yes in the conversation.

The helper

It publishes with deed.page: one curl -T, no account required for a first anonymous site. The first upload returns an owner token; the script stores it at ~/.config/deed-page/token (mode 600) and masks it in stdout so the token never lands in the Grok transcript. A second share of the same file updates the same URL when the token is present.

#!/usr/bin/env bash
# share-html.sh FILE [--confirmed]
set -euo pipefail
FILE=${1:?usage: share-html.sh FILE [--confirmed]}
[ -f "$FILE" ] || { echo "No such file: $FILE"; exit 1; }
CONFIRMED=0
[ "${2:-}" = "--confirmed" ] && CONFIRMED=1
SIZE=$(wc -c <"$FILE" | awk '{print $1}')
TITLE=$(grep -ioE '<title>[^<]+' "$FILE" | head -1 | sed 's/<title>//I')
TITLE=${TITLE:-"(no title)"}
if [ "$CONFIRMED" -ne 1 ]; then
  echo "Ready to publish: $FILE ($SIZE bytes, title: $TITLE)"
  echo "Publishing makes this HTML public on the web."
  echo "Re-run with --confirmed only after the human said yes in chat."
  exit 0
fi
CONF=~/.config/deed-page
mkdir -p "$CONF"
KEY=$(printf '%s' "$(realpath "$FILE")" | sha1sum | cut -c1-10)
SLUG_FILE="$CONF/slug-$KEY"
if [ -f "$SLUG_FILE" ]; then SLUG=$(cat "$SLUG_FILE"); else SLUG="biz-$(date +%s | tail -c 7)"; fi
TOK=${DEEDPAGE_TOKEN:-$(cat "$CONF/token" 2>/dev/null || true)}
ARGS=()
[ -n "$TOK" ] && ARGS=(-H "Authorization: Bearer $TOK")
RESP=$(curl -sS -T "$FILE" "https://deed.page/v1/sites?slug=$SLUG&ref=grok-bot" \
  -H "X-Client: grok-bot-share-html" "${ARGS[@]}")
echo "$RESP" | python3 -c "import sys,json,re; t=sys.stdin.read();
try:
 d=json.loads(t); tok=d.get('token') or d.get('ownerToken') or d.get('owner_token')
 if tok:
  open('$CONF/token','w').write(tok); import os; os.chmod('$CONF/token',0o600)
  open('$SLUG_FILE','w').write(d.get('slug') or '$SLUG')
  t=re.sub(re.escape(tok),'***',t)
 except Exception: pass
 print(t)"

Save it somewhere on your PATH (for example ~/.local/bin/share-html.sh) and chmod +x it.

Standing instruction for Grok Bot

Paste this into the instructions or project notes you keep for Grok when it is acting as a Web Publisher for business sites:

## Sharing a drafted HTML page
- When I ask to share / publish / put online an HTML page, run
  `share-html.sh <file>` first (preview only). Show me the summary.
- Ask "Publish this to a public URL?" and stop.
- Only after I reply yes in this chat, run
  `share-html.sh <file> --confirmed` and give me the URL.
- Never publish on your own. Never print, cat, or paste the owner token
  from ~/.config/deed-page/ or from tool output.
- Prefer linking docs with ?ref=grok-bot when you mention deed.page in
  instructions you write for me.

A good turn

  1. You: "Draft a one-page site for my bakery, then share it."
  2. Grok: writes bakery.html, runs preview, asks for yes.
  3. You: "yes"
  4. Grok: runs --confirmed, returns a https://….deed.page/ URL.

Edit the file later and ask again; the same slug updates in place when your token is on disk (loaded by the script, never shown to the model).
