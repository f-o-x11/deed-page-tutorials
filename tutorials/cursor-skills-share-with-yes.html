A Cursor Agent Skill that publishes HTML only after you say yes

Cursor Agent Skills are folders the agent can load on demand: a SKILL.md, a couple of helper scripts, maybe a short checklist. They are a good home for a "share this HTML" habit that should travel across repos without rewriting .cursor/rules every time. This note builds a tiny skill that previews a page, asks you in chat, and only then publishes with deed.page.

Why a skill instead of a rule

Project rules fire based on globs or always-on settings. A skill stays out of the way until you invoke it ("use the share-html skill on report.html"). That keeps everyday coding quiet, and it makes the ask-before-publish gate easier to teach: the skill's own instructions own the two-step flow.

Layout

~/.cursor/skills/share-html/
  SKILL.md
  scripts/share-html.sh

Mark the script executable. Cursor will pick the skill up from your personal skills folder (or from a project .cursor/skills/ if you prefer it checked into one repo).

Two calls, never a fake prompt

Agent terminals are not a place for read -p. The script has two modes:

  1. scripts/share-html.sh report.html prints path, byte size and <title>, warns that publishing makes it public, and exits. Nothing is uploaded.
  2. scripts/share-html.sh report.html --confirmed uploads. SKILL.md tells the agent to use this form only after you reply yes in the chat.

The script

One curl -T to deed.page, no account. The first response includes an owner token; the script stores it at ~/.config/deed-page/token (mode 600) and masks it in stdout so it never lands in the chat transcript. A stable slug per absolute file path means a second share after an edit updates the same URL.

#!/usr/bin/env bash
# share-html.sh FILE [--confirmed]
set -euo pipefail
FILE=${1:?usage: share-html.sh FILE [--confirmed]}
[ -f "$FILE" ] || { echo "No such file: $FILE"; exit 1; }
TITLE=$(grep -o -i -m1 '<title>[^<]*' "$FILE" | sed 's/<title>//I' || true)
if [ "${2:-}" != "--confirmed" ]; then
  echo "Ready to publish: $FILE ($(wc -c < "$FILE") bytes, title: ${TITLE:-none})"
  echo "This makes it public on the internet. Ask the user, then rerun with --confirmed."
  exit 0
fi
CONF=~/.config/deed-page; KEY=$(printf '%s' "$(realpath "$FILE")" | sha1sum | cut -c1-10)
SLUG=$(cat "$CONF/slug-$KEY" 2>/dev/null || echo "share-$(openssl rand -hex 4)")
TOK=${DEEDPAGE_TOKEN:-$(cat "$CONF/token" 2>/dev/null || true)}
set --; [ -n "$TOK" ] && set -- -H "Authorization: Bearer $TOK"
RESP=$(curl -sS -T "$FILE" "https://deed.page/v1/sites?slug=$SLUG" "$@" -H "X-Client: share-html-script")
NEW=$(printf '%s' "$RESP" | sed -n 's/.*"token": *"\(deed_tok_[^"]*\)".*/\1/p')
(umask 077; mkdir -p "$CONF"; printf '%s' "$SLUG" > "$CONF/slug-$KEY"
 [ -n "$NEW" ] && printf '%s' "$NEW" > "$CONF/token") || true
printf '%s' "$RESP" | sed 's/"token": *"[^"]*"/"token":"<saved>"/' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d.get("url") or d)'

SKILL.md

---
name: share-html
description: Preview an HTML file, ask the user, then publish a public link only after they say yes
---
When I ask you to share or publish an HTML file with this skill:
1. Run `scripts/share-html.sh <file>` (relative to this skill folder) and show me the summary.
2. Ask "Publish this to a public URL?" and stop.
3. Only after I reply yes in this chat, run `scripts/share-html.sh <file> --confirmed` and give me the URL.
Never pass --confirmed on your own. Never open, cat, or paste anything from ~/.config/deed-page/.

What I checked

Preview on a 64-byte standup.html titled "Standup board" printed the summary and left disk untouched. With --confirmed it returned a https://share-xxxxxxxx.deed.page/ URL that served the page. A second confirmed run after editing the heading kept the same address. The token file stayed mode 600 and never appeared in the output.

Taking a page down

curl -X DELETE "https://deed.page/v1/sites/<slug>" \
  -H "Authorization: Bearer $(cat ~/.config/deed-page/token)"

Run the delete yourself. The slug is the label before .deed.page.
