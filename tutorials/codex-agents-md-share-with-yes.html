Give Codex a "share this page" step that waits for your yes

Codex is happy to write a benchmark table, a migration checklist or a small dashboard as an HTML file. Getting that file in front of someone else is still a manual job: zip it, upload it somewhere, paste a link. This walkthrough adds one shell script and a short section in a global AGENTS.md file, so you can tell Codex "share bench.html" in any repo and get back a public link, but only after it has shown you what it is about to publish and you have said yes.

Where the rule lives

Codex reads AGENTS.md files for instructions. A file in your Codex home folder (~/.codex/AGENTS.md) applies to every project, and an AGENTS.md in a repo adds project rules on top. A sharing rule is personal rather than project-specific, so the global file is the natural place. Keep the script next to it in ~/.codex/bin/share-html.sh and mark it executable.

Two calls instead of a prompt

The script never asks "Publish? [y/N]" on its own, because the agent's shell is not a terminal you are watching and the agent could simply answer for you. It is split into two calls:

1. share-html.sh bench.html prints the file size and page title, says that publishing makes it public, and exits. Nothing is uploaded and nothing is written to disk. 2. share-html.sh bench.html --confirmed uploads the file and prints the URL.

The AGENTS.md text tells Codex that the second call is only allowed after you answer yes in the chat. If you run Codex with network access turned off in its sandbox, the upload will also need your approval to reach the network, which gives you a second checkpoint.

The script

It publishes with deed.page, where a single HTML file goes up with one curl -T and no account. The first upload returns an owner token; the script stores it in ~/.config/deed-page/token (mode 600) and masks it in its output so it never lands in the Codex transcript. It also remembers which address belongs to which file, so sharing the same file again updates the existing link instead of creating a new one.

#!/usr/bin/env bash
# share-html.sh FILE [--confirmed]
# Without --confirmed: print a preview summary and exit (nothing leaves the machine).
# With --confirmed: publish FILE to a public deed.page URL. Agents pass --confirmed
# only after the human said yes in chat. The owner token is saved, never printed.
set -euo pipefail
FILE=${1:?usage: share-html.sh FILE [--confirmed]}
[ -f "$FILE" ] || { echo "No such file: $FILE"; exit 1; }
TITLE=$(grep -o -i -m1 '<title>[^<]*' "$FILE" | sed 's/<title>//I' || true)
if [ "${2:-}" != "--confirmed" ]; then
  echo "Ready to publish: $FILE ($(wc -c < "$FILE") bytes, title: ${TITLE:-none})"
  echo "This makes it public on the internet. Ask the user, then rerun with --confirmed."
  exit 0
fi
CONF=~/.config/deed-page; KEY=$(printf '%s' "$(realpath "$FILE")" | sha1sum | cut -c1-10)
SLUG=$(cat "$CONF/slug-$KEY" 2>/dev/null || echo "share-$(openssl rand -hex 4)")
TOK=${DEEDPAGE_TOKEN:-$(cat "$CONF/token" 2>/dev/null || true)}
set --; [ -n "$TOK" ] && set -- -H "Authorization: Bearer $TOK"
RESP=$(curl -sS -T "$FILE" "https://deed.page/v1/sites?slug=$SLUG" "$@" -H "X-Client: share-html-script")
NEW=$(printf '%s' "$RESP" | sed -n 's/.*"token": *"\(deed_tok_[^"]*\)".*/\1/p')
(umask 077; mkdir -p "$CONF"; printf '%s' "$SLUG" > "$CONF/slug-$KEY"
 [ -n "$NEW" ] && printf '%s' "$NEW" > "$CONF/token") || true
printf '%s' "$RESP" | sed 's/"token": *"[^"]*"/"token":"<saved>"/' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d.get("url") or d)'

The section for ~/.codex/AGENTS.md

## Sharing HTML files
- When I ask you to share an HTML file, run `~/.codex/bin/share-html.sh <file>` first
  and show me the summary it prints.
- Then ask "Publish this to a public URL?" and stop. Only after I reply yes in this
  conversation, run `~/.codex/bin/share-html.sh <file> --confirmed` and give me the URL.
- Never add --confirmed on your own initiative. Never open, cat or print anything in
  ~/.config/deed-page/, and never paste the owner token anywhere.
- If I ask you to update a link I already shared, show the summary again, wait for my
  yes, then rerun with --confirmed. The address stays the same.

What happened when I ran it

I tested the script by hand the same way Codex would call it, with a 64-byte bench.html titled "Codex bench table". The preview call printed Ready to publish: bench.html (64 bytes, title: Codex bench table) and created no files at all. The --confirmed call printed a https://share-xxxxxxxx.deed.page/ address that served the page. After editing the heading and running --confirmed again, the same address showed the new version. The token file had mode 600 and its value never appeared in the output.

Removing a page

curl -X DELETE "https://deed.page/v1/sites/<slug>" \
  -H "Authorization: Bearer $(cat ~/.config/deed-page/token)"

The slug is the part of the address before .deed.page. In my test the DELETE returned 200 and the address returned 404 a few seconds later. Run this one yourself rather than asking Codex to, since it reads the token.
